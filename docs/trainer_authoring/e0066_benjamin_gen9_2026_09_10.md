## Shared AI correction and necessary regression

`src/battle_ai_main.c`, `GetWindAbilityScore`: previously Wind Power earned
a charge reward simply for holding an Electric attack. It now requires an
Electric move with positive cached native damage against at least one living
opponent. Ground/absorbing targets no longer justify an unusable charge.
This reuses the existing four-move/four-battler cache; no fresh damage
simulation, allocation, recursion or branching search. Wind Rider's stat
reward is unchanged. Useful Electric damage or independent speed payoff
still allows Tailwind; this is not a ban on wind-ability setups.

The doubles Tailwind speed-crossing calculation now excludes fainted foes and
a fainted partner. Before this fix, eliminated Xatu's Speed could still create
a reason for Persian to receive Tailwind against a lone slower Mudbray or
Pachirisu. The existing no-payoff penalty can now apply correctly.

One retained native regression in `test/battle/ai/emerald_champions_plans.c`
freezes the old Life Orb party and a two-turn Mudbray/Xatu reproduction,
independent of current trainer edits. It verifies no Tailwind PP is spent
after Xatu falls. Fixed run passes in `work/benjamin-wind-regression-fixed.log`.
Temporarily reverting only these two scoring changes makes the assertion fail
(14PP rather than15) in `work/benjamin-wind-regression-counterfactual.log`.
Both fixes were explicitly restored before final native verification.
The combined counterfactual establishes regression value, not separate proof
of each change in isolation. No extra static gate or permanent trainer suite.

Opponent Follow Me prediction remains imperfect: the existence of a vulnerable
foe does not promise the attack will reach it through redirection. This bounded
fix does not claim to solve that separate targeting limitation.
