## Shared Pollen Puff repair

The initial actual-team review stops at `GetMoveEffectArg_MoveProperty`:
Pollen Puff has EFFECT_HIT_ENEMY_HEAL_ALLY, not the Heal Pulse effect whose
union argument stores Floral Healing. The pair evaluator read that argument
unconditionally while considering an allied heal. Restrict the Floral Healing
argument read to EFFECT_HEAL_PULSE in `battle_ai_pair.c`.

The real healing command has the same invalid read when Grassy Terrain is
active. Pollen Puff's battle script deliberately jumps to the Heal Pulse
script, so apply the same effect guard in `BS_TryHealPulse`. Do not weaken the
getter assertion or change Pollen Puff's data. Standard half healing, genuine
Floral Healing's terrain bonus and Mega Launcher Pulse handling are preserved.
These are small shared fixes, not per-Victoria workarounds or added search.

`work/victoria-gen9-baseline.log` reproduces the evaluator assertion;
`work/victoria-gen9-puff-fixed-baseline.log` runs the original team after repair.
`work/pollen-puff-grassy-before.log` separately reproduces the actual command
assertion. `work/pollen-puff-grassy-after.log` passes after its repair, but was
not enough to establish exact healing: see the subsequent damage defect below.
Extend the existing shared partner-healing regression with a Pollen Puff/
Grassy Terrain parameter rather than adding another test group. The healer
